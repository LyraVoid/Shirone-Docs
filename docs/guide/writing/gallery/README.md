`:::grid` 是图片画廊容器：把普通 Markdown 图片排成响应式网格，统一卡片比例并自动启用灯箱浏览。本篇同时讲解多图文章的文件组织方式。

## 最小语法

````markdown
:::grid
![图片描述](./image-1.webp)

![图片描述](./image-2.webp)
:::
````

规则：每张图片独占一段（图片间空行分隔）；容器内只放图片，段落、列表、代码块写在容器外。

## 参数

参数写在起始指令的花括号内：`:::grid{参数="值"}`。

| 参数 | 可选值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `columns` | 1 ~ 6 的整数 | `3` | 桌面端每行列数，非法值回退 3 |
| `aspect` | 正比例，如 `16/9`、`3/4`、`1/1` | `16/10` | 卡片显示比例（非原图比例） |
| `fit` | `cover` / `contain` | `cover` | `cover` 裁切填满；`contain` 完整显示可能留白 |

````markdown
:::grid{columns="3" aspect="16/9" fit="cover"}
![第一张](./image-1.webp "可选说明文字")

![第二张](./image-2.webp)
:::
````

## 说明文字与替代文本

图片的 alt 文本同时充当无障碍替代文本与默认说明文字；有 title 时 title 优先作为说明：

```markdown
![无障碍替代文本](./image.webp "显示在图片下方的说明")
```

同一行内说明文字底部对齐，长说明换行不会让其他卡片错位。

## 布局与裁切

响应式规则：桌面按 `columns` 列；768px 以下最多两列；480px 以下单列。

- `cover`（推荐默认）：居中裁切填满卡片，画廊观感统一
- `contain`：完整显示原图不裁切，比例不一致时露出主题背景——适合不可裁切的图（长截图、含关键边缘信息的图）
- 想完整显示又无留白：把 `aspect` 设为接近原图比例，或单独一列

## 灯箱浏览

点击画廊任意图片打开 Fancybox 灯箱：缩放、旋转、全屏、缩略图、方向键导航。**导航范围限于当前 `:::grid` 容器**——每个画廊是独立灯箱组，与文章其他图片互不混合。

## 文件组织：多图文章的推荐结构

图片多的文章用「目录 + index.md」组织，图片与文章同目录：

```text
src/content/posts/
├── my-trip.md              # 单图或少图文章
└── my-gallery/             # 多图文章
    ├── index.md            # 文章正文
    ├── cover.webp          # 封面（frontmatter image: ./cover.webp）
    ├── photo-1.webp
    ├── photo-2.webp
    └── photo-3.webp
```

正文用相对路径引用：`![描述](./photo-1.webp)`。好处：图片随文章移动、删除文章不残留孤儿图片、frontmatter 封面写 `./cover.webp` 即可。

::: tip 格式建议
生产环境优先使用 `.webp`（体积小、质量好）。原图过大时先压缩——`cover` 模式虽会裁切显示，但原图仍会被完整加载（灯箱展示用）。
:::

## 实战示例

**三列横图画廊**

````markdown
:::grid{columns="3" aspect="16/9"}
![横幅一](./landscape-1.webp "第一张")

![横幅二](./landscape-2.webp "第二张")

![横幅三](./landscape-3.webp "第三张")
:::
````

**两列大图预览**

````markdown
:::grid{columns="2" aspect="1/1"}
![方形一](./square-1.webp)

![方形二](./square-2.webp)
:::
````

**不可裁切的长截图**

````markdown
:::grid{columns="1" aspect="16/9" fit="contain"}
![完整长截图](./screenshot.webp "点击查看原图")
:::
````

## 常见问题

**画廊没渲染，图片竖排显示**

检查 `:::grid` 与 `:::` 是否配对、图片间是否空行、容器内是否混入了其他内容——非法结构会整体保留为普通 Markdown。

**图片被裁掉了重要内容**

`cover` 居中裁切的代价。改用 `fit="contain"`，或把关键信息移出图片边缘（源码注释也提醒：临界内容的图配清晰说明文字，引导读者点开灯箱看原图）。

**为什么 480px 以下不按我设的列数**

响应式规则强制：768px 以下最多两列、480px 以下单列，保证手机可读性，不可覆盖。

**六列之后还能更多吗**

`columns` 上限 6。更密的缩略图需求建议拆分多个画廊（各自独立灯箱组反而更好导航）。
